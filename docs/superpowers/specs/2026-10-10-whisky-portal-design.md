# Whisky Portal (가칭) — 설계 문서

작성일: 2026-10-10

## 1. 의도와 이유

사용자는 한국에 산다. Stagg, Jack Daniel's Single Barrel Barrel Proof 같은 미국 위스키를 사고 싶은데, 미국 매장 사이트는 쓰기 불편하고 한국에서 가격을 비교하기도 어렵다. 그래서 맨해튼에 사는 누나에게 구매를 부탁한다. 누나는 위스키를 잘 모른다. 지금은 카톡으로 매장 링크와 사진을 보내는 방식이다.

이 포털이 하는 일:
1. 브루클린, 뉴저지, LA(CA) 매장에서 원하는 병의 **가격과 재고**를 한 화면에서 비교한다.
2. 위스키를 모르는 사람도 헷갈리지 않는 **구매 카드 링크**를 만들어 카톡으로 보낸다.
3. 관심 병이 들어오거나 싸지면 **텔레그램으로 알린다**.

장기적으로는 누구나 쓰는 공개 웹사이트로 연다. 첫 버전은 사용자와 누나가 쓰는 도구지만, 공개를 막는 설계는 하지 않는다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 지역 우선순위는 1순위 브루클린과 뉴저지(맨해튼보다 싸고 누나가 직접 갈 수 있음), 2순위 LA(누나가 LA에 갈 때, CA가 더 싸면 거기서 산다).
- 매장에서 직접 사는 것을 기본으로 본다(배송비를 피하려고). 온라인 주문은 보조 수단이다.
- 매장마다 이름이 달라도 같은 병은 묶어서 가격순으로 비교한다.
- 구매 카드 링크를 카톡에 붙이면 미리보기에 사진, 이름, 가격이 나온다.
- 관심 병 알림을 텔레그램으로 보낸다.

**비목표 (첫 버전)**
- 회원가입과 로그인. 구조만 나중에 붙일 수 있게 둔다.
- 결제, 주문 대행, 배송 계산.
- 리뷰와 커뮤니티.
- 봇 차단된 매장(Total Wine, K&L, Bottle King, City Wines 등) 지원.

**반목표: 이렇게 되면 실패다**
- **가격이나 재고가 틀려서 누나가 헛걸음하는 것. 사용자가 꼽은 최악의 상황이다.** 모든 설계 결정에서 이것을 가장 먼저 따진다.
- 비슷한 다른 병(다른 배치, 프루프, 용량, Stagg 대 Stagg Jr. 대 George T. Stagg)을 같은 병으로 보여줘서 엉뚱한 병을 사는 것.
- 매장 서버에 부담을 주거나 봇 차단을 우회하는 크롤링.

## 3. 정확성 원칙 (반목표에서 나온 요구사항)

- **신선도를 항상 표시한다.** 모든 가격과 재고 옆에 "N시간 전 확인"을 붙인다. 일정 시간(빌더가 정하되 기본 24시간)이 지나면 "오래된 정보"로 눈에 띄게 표시한다.
- **구매 직전 재확인.** 구매 카드에 "지금 다시 확인" 버튼을 둔다. 누르면 해당 상품 하나를 매장에서 실시간으로 다시 조회한다(Shopify `/products/<handle>.js`). 카드를 만들거나 열 때도 자동으로 한 번 재확인한다.
- **매장별 재고 신뢰도.** 조사해 보니 일부 매장의 재고 표시는 믿기 어렵다. Liquor Cave는 거의 전부 "있음", CoolVines는 거의 전부 "없음"으로 나온다. 매장마다 신뢰도(높음/낮음)를 두고, 낮은 매장은 "재고 표시 부정확, 방문 전 전화 확인"이라고 명확히 표시한다. 온라인 재고와 매장 진열 재고는 다를 수 있다는 점도 카드에 적는다.
- **전화 버튼.** 구매 카드에 매장 전화번호와 바로 거는 버튼을 넣는다. 누나가 방문하기 전에 전화로 확인할 수 있게 한다.
- **병 구분 정보를 크게 표시한다.** 프루프, 배치, 용량, 연식을 상품명과 별도로 크게 보여준다.
- **보수적으로 묶는다.** 확신이 없으면 같은 병으로 묶지 않는다. 잘못 묶이는 것보다 따로 나오는 쪽이 낫다.

## 4. 데이터 소스

모든 소스는 Shopify 공개 엔드포인트 `https://<domain>/products.json?limit=250&page=N`을 쓴다. 이 엔드포인트는 `variants[].price`와 `variants[].available`(재고 있음/없음 불리언)을 제공한다. 남은 수량은 제공하지 않는다.

매장 주소, 좌표, 전화번호, 매장이 여러 곳인 경우의 처리는 빌더가 확인해서 매장 설정에 넣는다.

**알려진 함정**
- **통화.** Shopify Markets를 쓰는 매장(확인된 곳: De Wine Spot)은 한국 IP로 요청하면 원화 가격을 준다. 항상 `Cookie: localization=US; cart_currency=USD`를 보내고, 받은 통화가 USD인지 확인한다. USD가 아니면 저장하지 않는다.
- **위스키가 아닌 상품.** Jack Daniel's 칵테일 캔이나 $2.99짜리 미니어처 같은 것도 섞여 나온다. 위스키 분류와 용량 파싱이 필요하다.
- **차단된 곳.** 막힌 매장은 우회하지 않는다. robots.txt를 지킨다.

**크롤링 예절:** 요청 사이 1초 이상 쉬고, 크롤러임을 알리는 User-Agent를 쓰고, 하루 몇 번만 돈다. 매장 추가는 설정 파일에 매장 하나를 넣는 것만으로 되어야 한다(Shopify 어댑터). 나중에 다른 플랫폼 어댑터를 붙일 수 있게 한다.

## 5. 화면과 기능

**검색과 비교 (사용자용, 한국어 UI)**
- "Stagg"처럼 검색하면 같은 병끼리 묶어서 보여준다. 각 묶음 안에서 매장별 가격, 재고, 확인 시각을 가격순으로 나열한다.
- **지역 표시 (사용자 결정):** 기본 결과는 브루클린과 뉴저지만 보여준다. CA 매장은 아래에 "LA 갈 때" 섹션으로 따로 보여주고, 위 목록과 섞어서 정렬하지 않는다.
- 각 섹션 안에서는 재고 있는 매장을 먼저, 그다음 세금 포함 예상가 순으로 정렬한다. 지역(브루클린 / 뉴저지 / CA) 필터와 가격 범위, 재고만 보기 필터를 둔다.
- **세금 (Claude가 정함):** 매장마다 판매세율 설정을 둔다(대략 NY 8.875%, NJ 6.625%, CA는 매장 소재지 세율). 표시 가격과 "세금 포함 예상가"를 함께 보여주고, 매장 간 비교와 정렬은 세금 포함가로 한다. 관심 목록의 목표 가격은 표시 가격(세전) 기준이다.
- 결과마다 "구매 카드 링크 복사" 버튼을 둔다.

**구매 카드 (누나용, 상품·매장 정보는 영어 원문)**
- 상품(매장의 특정 상품) 하나당 고유 링크를 만든다. 로그인 없이 열린다.
- 카톡 미리보기용 OG 태그를 넣는다(병 사진, 이름, 가격). **(Claude가 정함)** 카톡은 미리보기를 오래 저장하므로, 미리보기의 가격에는 항상 확인 날짜를 붙인다(예: "10/10 기준 $64.99"). 링크를 열면 실제 페이지에서 다시 조회한 최신 값을 보여준다.
- 내용: 큰 병 사진, 정확한 상품명, 프루프·배치·용량, 가격, 확인 시각과 신선도 상태, 재고 신뢰도 경고, "지금 다시 확인" 버튼, 매장 이름·주소, 구글 지도 길찾기 버튼, 전화 걸기 버튼, 매장 원래 상품 페이지 링크.
- "점원에게 보여주기" 모드: 큰 글씨로 "Do you have this bottle?"과 상품명·사진만 띄운다.

**지도**
- Leaflet + OpenStreetMap으로 매장 위치를 표시한다. 마커를 누르면 그 매장의 위스키 목록이 나온다. 검색 결과에서 그 병이 있는 매장만 표시하는 기능도 둔다.

**관심 목록과 텔레그램 알림**
- **알림 범위 (사용자 결정):** 기본 단위는 **제품 계열**이다. 예를 들어 "Stagg"를 등록하면 배치나 프루프에 상관없이 Stagg가 들어오면 알린다. 단 Stagg Jr.와 George T. Stagg는 서로 다른 계열로 구분한다. 원하면 특정 배치나 정확한 병 하나로 좁힐 수 있다.
  - 그래서 데이터 구조에는 **제품 계열**(예: Stagg)과 그 아래 **정확한 병**(배치·프루프·용량이 같은 것)의 두 단계가 필요하다. 계열 분류도 3장의 보수적 원칙을 따르고, 애매하면 사람이 고칠 수 있게 한다.
- 선택적으로 목표 가격과 지역을 정한다.
- 크롤링이 끝날 때마다 아래 경우에 텔레그램으로 알린다. 알림에는 구매 카드 링크를 넣는다.
  - 품절이던 병이 재고 있음으로 바뀐 경우
  - 새 매장에 그 병이 처음 올라온 경우
  - 가격이 목표 가격 아래로 떨어진 경우
- 같은 알림을 반복해서 보내지 않는다.
- 첫 버전은 텔레그램 채팅 하나(사용자)로 보낸다. 나중에 누나 등 여러 명이 받을 수 있게 구조를 잡는다.

**한국 가격 비교 (2026-10-10 추가, 사용자 요청)**
- 목적: "한국에서도 비슷하면 미국에서 살 필요 없다". 미국에서 사 오는 게 얼마나 이득인지 눈으로 바로 판단하게 한다. **순수 가격 비교만 한다.** 면세 한도, 관세 추정, 병 수 제한은 넣지 않는다(사용자 결정). 병은 누나가 한국에 올 때 직접 들고 온다.
- 한국 가격 출처는 **데일리샷**(dailyshot.co)이다. robots.txt가 허용하고, 차단 우회도 필요 없다.
  - 검색 결과 페이지 `https://dailyshot.co/m/search/result?q=<검색어>`의 `__NEXT_DATA__`에 상품별 `top_product_id`, `name`(한글), `en_name`, `price`(원), `thumbnail_image`가 들어 있다.
  - 상품 페이지 `https://dailyshot.co/m/item/<id>`의 JSON-LD `offers`(AggregateOffer)에 `lowPrice`, `highPrice`, `offerCount`, `priceCurrency: KRW`가 들어 있다.
- **연결은 사람이 확인한다 (Claude가 정함).** 한국 상품명과 미국 상품명은 형식이 달라서 자동 연결은 오매칭 위험이 크다(반목표). 그래서 미국의 "같은 병" 묶음 하나에 데일리샷 상품 하나를 연결한다. 시스템이 데일리샷 검색 후보를 보여주고 사용자가 고른다. 연결한 뒤에는 크롤링할 때마다 데일리샷 최저가를 자동 갱신한다.
- 계산
  - 미국 원화가 = 미국 세금 포함가 × 그날 USD→KRW 환율. 환율은 무료 API에서 하루 한 번 받는다(Claude가 정함).
  - 이득 = 데일리샷 최저가 − 미국 원화가. 이득률 = 이득 ÷ 데일리샷 최저가.
  - 판정 (Claude가 정함): 15% 이상이면 "사 올 만함"(초록), 0~15%면 "비슷함"(회색), 음수면 "한국이 더 쌈"(빨강).
- 표시
  - 사용자 쪽 검색 결과의 병 묶음 머리에 "한국 최저 649,000원 · 미국 약 252,000원 · 397,000원(61%) 이득"처럼 색으로 표시한다. 기준은 그 섹션(메인 또는 CA)에서 재고 있는 가장 싼 매장이다.
  - **이득 순위 화면:** 연결된 병들을 이득률 순으로 정렬해 미국과 한국 가격을 막대로 비교한다.
  - 각 값에는 확인 시각과 데일리샷 링크를 붙인다.
  - 누나용 구매 카드에는 넣지 않는다(Claude가 정함).

**가격 이력**
- 가격이나 재고가 바뀔 때만 기록한다. 상세 화면에 간단한 추이를 보여준다(README의 확장 계획).

**언어:** UI는 한국어와 영어를 모두 고려한다. 첫 버전 기본은 한국어다. 구매 카드의 상품명과 매장 정보는 영어 원문을 그대로 쓴다.

## 6. 만드는 방법 (사용자가 Claude에게 맡겼고, Claude가 정한 것)

| 영역 | 선택 |
|---|---|
| 웹 | 기존 Next.js 16 프로젝트(`D:\whisky-xy`, App Router, TypeScript, Tailwind 4) + shadcn/ui |
| DB | Supabase Postgres 무료 플랜 |
| 크롤러 + 알림 | Node/TypeScript 스크립트. GitHub Actions 예약 실행(몇 시간마다). 웹 코드와 같은 저장소에서 공용 라이브러리를 함께 쓴다 |
| 배포 | Vercel 무료 플랜 |
| 지도 | Leaflet + OpenStreetMap (API 키 없음) |
| 알림 | 텔레그램 Bot API |

- README에 있던 Puppeteer, Mapbox, PostGIS는 쓰지 않는다. 데이터가 JSON으로 오기 때문에 브라우저 자동화가 필요 없다. 매장 수가 적어서 공간 쿼리도 필요 없다.
- 비밀 값(Supabase 키, 텔레그램 토큰 등)은 환경 변수와 GitHub Secrets로만 관리하고 코드에 넣지 않는다. DB 쿼리는 파라미터 바인딩을 쓴다. 외부 상품 HTML(body_html)은 렌더링하지 않는다. "지금 다시 확인" API는 등록된 매장 도메인만 조회하게 해서 남용을 막는다.
- 상품 사진은 매장 CDN 이미지를 링크로만 쓰고 복사해 저장하지 않는다.
- **공개 대비 (Claude가 정함):** 매장마다 "공개 노출 허용" 플래그를 처음부터 둔다. 첫 버전에서는 전부 허용이다. 출처 매장 이름과 원래 상품 페이지 링크는 모든 화면에 항상 표시한다.

## 7. 빌더에게 맡기는 것

- DB 스키마의 세부 구조, 같은 병으로 묶는 알고리즘(정규화 규칙, 프루프·배치·용량 추출 방식), 위스키 분류 규칙. 단 3장의 보수적 원칙을 따른다.
- 크롤링 주기(하루 몇 번 범위 안에서), 신선도 기준 시간, 재시도와 에러 처리.
- 화면 레이아웃과 시각 디자인, 컴포넌트 구성.
- 관심 목록 관리 UI의 첫 버전 접근 보호 방식. 공개 사이트가 되기 전이므로 간단한 비밀 키나 환경 변수 기반으로 충분하다.
- 테스트 전략.
